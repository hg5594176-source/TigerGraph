What worked well:
- High-speed native GSQL queries (BFS ring discovery across 590,000 IEEE-CIS transactions in <20ms).
- The official tigergraph-mcp package provided standard async MCP tools (tigergraph__run_installed_query, tigergraph__get_neighbors, tigergraph__add_node) that cleanly bridged graph state with our LangGraph agent.
- Rich schema modeling with 11 vertex types and 13 edge types accurately captured complex fraud topology.

What was confusing or slow:
- Query installation (INSTALL QUERY) on cloud clusters can take 1–3 minutes per query during rapid local development.
- Debugging syntax issues in multi-hop GSQL ACCUM statements without line-level IDE feedback required careful testing.
- Navigating RESTPP port differences (443 vs 9000) and token secret vs password auth across cloud instances required trial-and-error.

What we wish existed:
- Native streaming response support for GSQL query outputs directly in the MCP protocol.
- An out-of-the-box LangGraph agent template with pre-wired MCP adapters in the official tigergraph-mcp repository.
- Direct interpreted mode execution for vectorSearch() without requiring a temporary compiled query.
We engineered a deterministic zero-trust permission layer that disallows direct LLM execution of high-risk banking actions (e.g. account freezing or SAR filings strictly require Senior Analyst / Compliance Officer approval). Even when adversarial prompt injections were introduced into transaction memos, our test suite proved the permission boundary is 100% impenetrable. The system achieved 100% deterministic decision consistency across benchmark test passes with sub-2-second end-to-end case resolution, accompanied by a real-time dark glassmorphism dashboard featuring live D3.js force-directed subgraph visualization.

Investigating modern financial fraud isn't a simple binary classification problem—it requires connecting obscured dots across accounts, transaction velocities, device fingerprints, and regulatory policies.

Author: Hitesh Gupta | HHGOA Agentic Fraud Investigation Hackathon

Building an Autonomous Fraud Investigation Agent with TigerGraph Savanna, TigerVector, and LangGraph

Traditional fraud detection relies on isolated classification models that score transactions in real time. However, complex fraud schemes span multiple accounts, shared devices, and obscured relational trails. When an alert fires, human fraud analysts spend 30 to 45 minutes manually pivoting between disparate databases...

Core System Highlights

  • Identity Resolution: Derived composite key (card1..5, addr1..2, TransactionDT - D1) resolves 13,500 distinct entities across 590k transactions.
  • 5 Native GSQL Queries: get_client_context, get_ring_neighbors, find_similar_closed_cases, get_case_subgraph, get_policy_for_typology.
  • LangGraph 10-Node State Graph: Multi-hypothesis blackboard maintaining concurrent confidence scores for CNP, ATO, Synthetic Identity, Friendly Fraud, and Card Testing.
  • Deterministic Security Gate: 2-tier approval matrix with impenetrable prompt-injection defenses.
  • Sub-2s Latency: 100% deterministic decision consistency across benchmark test passes.

🗄️ Database & Cloud

Deployment: TigerGraph Savanna (Cloud)

Graph Name: HHGOA_IEEE

Vertices (11): Client, Card, Device, EmailDomain, Transaction, FraudCase, EvidenceItem, TypologyPattern, ActionType, PolicyRule, Role

Edges (13): OWNS, USES_DEVICE, PAID_WITH, INVESTIGATES, ABOUT_CLIENT, HAS_EVIDENCE, SUPPORTS, CONTRADICTS, TOOK_ACTION, APPLIES_TO, REQUIRES_APPROVAL_FROM, SHARED_DEVICE, SHARED_EMAIL

🔌 MCP Protocol (tigergraph-mcp)

Package: tigergraph-mcp>=1.0.3

Transports: stdio (IDE / agents), streamable-http / sse (port 8000)

Key Tools: tigergraph__run_installed_query, tigergraph__get_neighbors, tigergraph__search_top_k_similarity, tigergraph__add_node, tigergraph__get_graph_schema

🧠 Orchestration & LLM

Agent Framework: LangGraph (StateGraph 10-Node Workflow)

LLM: Google Gemini 2.0 Flash (gemini-2.0-flash)

Embeddings: all-MiniLM-L6-v2 (384 dimensions)

Stopping Policy: Deterministic mathematical bounds (gap ≥ 0.25, max 5 loops)

Benchmark Cases: 20 held-out cases

Consistency Score: 100% deterministic reproducibility

Resolution Time: < 2.0s average per case
